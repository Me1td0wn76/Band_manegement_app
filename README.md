# Riffboard — ライブの裏方管理アプリ

ライブの**裏方（撮影・照明・SNS・タイムキーパー・PA）の割り振り**と、**タイムテーブル（出演順・転換・開催時間）の作成**を行う、数十人規模のサークル向けアプリです。
バンドや楽器は管理しません。出演者はタイムテーブル上の名前と演奏時間だけを持ち、登録メンバーは裏方として割り振られます。
デザインは Riffboard デザインシステム（https://claude.ai/artifact/3Dxj2rUyk4mM2nTLHfF9at）に従っています。

- フロントエンド：React 19 + TypeScript + Vite（GitHub Pages で無料配信）
- バックエンド：Supabase 無料プラン（PostgreSQL・認証・Edge Function）
- Supabase を設定しなければ、ブラウザ内のデモデータで動きます（すぐ試せます）

## 機能

| 機能 | 画面 | 内容 |
| --- | --- | --- |
| ログイン・初期登録 | ログイン → 初期登録 | 幹部がメールアドレスと初期パスワードでメンバーを登録 → 本人が初回ログインでパスワードを設定し直す |
| 幹部ダッシュボード | ダッシュボード | 今月のイベント数・メンバー数・未割り当ての枠、次のライブまでのカウントダウン、割り振り状況、最近の活動 |
| イベントの登録・管理・表表示 | イベント管理 | 開場・開演・終演予定・転換・会場・定員・裏方の人数。状態タブと検索、並べ替えできる表、CSV 書き出し |
| タイムテーブル | タイムテーブル | 出演の追加・削除、ドラッグや矢印で出演順を入れ替え、休憩、転換を自動で挿入して各出演の時刻を計算 |
| 開催時間の自動調整 | タイムテーブル | 終演予定に合わせて、転換時間（5〜20分）→ 演奏時間の順に自動で調整。固定した出演（トリなど）は変えない |
| 出演順の自動編集 | タイムテーブル | 固定していない出演をシャッフル（くじ引き）、休憩を真ん中に挿入 |
| 裏方の自動割り振り | 裏方の割り振り | 役割ごとに「ライブ全体で固定」か「出演ごとに交代」か。担当回数の平準化・連続担当の回避・参加不可の除外 |
| 自動割り振り時の管理 | 裏方の割り振り | 枠のロック、重複・参加不可・幹部のみ違反の警告、人数の増減、履歴、元に戻す、確定 |
| 手動編集 | 裏方の割り振り | 枠をクリックして選ぶ、控えのメンバーをドラッグ、枠どうしの入れ替え |
| 役割の設定 | 役割の設定 | 役割の追加・編集（アイコン、単位、既定の人数、幹部のみ） |
| メンバーの登録・管理・閲覧 | メンバー管理 | 登録（初期パスワードの自動生成）、編集、パスワード再設定、無効化、削除、CSV 書き出し |
| 参加可否 | マイページ | 参加できないライブを登録すると、自動割り振りの候補から外れる |
| 幹部（admin）権限 | 権限設定ほか | 幹部＝管理者。PA など「幹部のみ」の役割は幹部だけが担当できる。DB 側も RLS とトリガーで保護 |

メンバー（一般）はダッシュボードの代わりに「マイページ」（自分の担当と時間、参加可否）が表示され、イベント・タイムテーブル・メンバーは閲覧のみです。

初期データの役割：

| 役割 | 単位 | 幹部のみ |
| --- | --- | --- |
| PA | ライブ全体 | ✓ |
| タイムキーパー | ライブ全体 | |
| SNS | ライブ全体 | |
| 照明 | 出演ごと | |
| 撮影 | 出演ごと | |

## 試してみる（デモモード）

```bash
npm install
npm run dev
```

ログイン画面の「Demo accounts」から選ぶとログインできます。

| 権限 | メールアドレス | パスワード |
| --- | --- | --- |
| 幹部 | admin@example.com | admin1234 |
| メンバー | member@example.com | member1234 |

デモのデータはこのブラウザの localStorage にだけ保存されます（サイドバーの「デモデータを初期化」で元に戻せます）。

```
│   ├── DataController.tsx   データの読み込みと操作（保存 → 活動ログ → 再読込）
│   ├── selectors.ts         集計（担当回数・空き枠・担当予定など）
│   ├── timetable.ts         タイムテーブルの計算・自動調整・シャッフル

├── migrations/        テーブル・RLS・関数
└── functions/admin-members/  メンバー作成などの幹部用 Edge Function
```

### タイムテーブルの計算

- 開演から順に「出演 → 転換 → 出演 …」と時刻を積み上げます。転換は出演と出演の間にだけ入り、休憩の前後には入りません
- 自動調整：終演予定に合わせて、まず転換時間だけで合わせ（5〜20分）、足りなければ固定していない出演の演奏時間を同じ割合で伸び縮みさせます（最短10分）

### 裏方の自動割り振り

ロックした枠は残したまま、ランダムな貪欲法を120回試して、いちばん良い案を採用します。

1. 埋まった枠が多い
2. このライブでの担当が偏らない
3. （連続担当を避ける）直前の出演でも担当した人が少ない
4. （平準化）今月の担当回数が少ない人に寄せる

参加不可のメンバーは候補から外れ、「幹部のみ」の役割は幹部だけが候補になります。「兼任を許可」がオフのときは、ライブ全体の役割の人は出演ごとの役割を持てず、同じ出演で2つの役割も持てません（「重複」になり確定できません）。

## Supabase で本番運用する

すべて無料枠に収まります（数十人規模なら DB・認証・Edge Function の上限に余裕があります）。

1. [Supabase](https://supabase.com) でプロジェクトを作る
2. SQL Editor で `supabase/migrations/20261122000000_init.sql` を実行する
3. Authentication → Users → **Add user** で最初の幹部を作る（「Auto Confirm User」をオン）。最初に作ったユーザーは自動で幹部になります
4. Authentication → Sign In / Providers で **Allow new users to sign up をオフ**にする（メンバー登録は幹部だけが行うため）
5. Edge Function をデプロイする

   ```bash
   npx supabase login
   npx supabase link --project-ref <プロジェクトID>
   npx supabase functions deploy admin-members
   ```

6. `.env.example` を `.env.local` にコピーし、Project Settings → API の URL と anon（publishable）キーを入れる

   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=...
   ```

7. `npm run dev` で起動し、手順3の幹部でログインする

### セキュリティ

- テーブルはすべて RLS 有効。閲覧は有効なメンバーのみ、書き込みは幹部のみ（自分の名前・参加可否の変更と活動ログの記録を除く）
- 一般メンバーが自分の権限・状態・メールアドレスを書き換えようとすると、トリガーで拒否されます
- 「幹部のみ」の役割に幹部以外を割り当てようとすると、トリガーで拒否されます
- auth ユーザーの作成・削除・パスワード再設定は service_role キーが必要なため、呼び出し元が幹部かを確認する Edge Function で行います（service_role キーはブラウザに出しません）
- anon キーは公開前提のキーです。データの保護は RLS で行っています

## GitHub Pages へのデプロイ

`.github/workflows/deploy.yml` が `main` への push でビルドと公開を行います。

1. リポジトリの Settings → Pages → Source を **GitHub Actions** にする
2. Settings → Secrets and variables → Actions に `VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY` を登録する（未登録ならデモモードで公開されます）
3. `main` に push する

`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。ルーティングはハッシュ（`#/events` など）なので、GitHub Pages でもページの再読み込みで 404 になりません。
